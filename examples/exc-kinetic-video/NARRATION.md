# 내레이션 대본 — Eleven v4

`out/exc-kinetic.mp4`(88초)를 **수정 없이** 쓰기 위한 한국어 내레이션이다. 화면 문구가 뜨는 시각에 맞춰 목소리가 따라 읽고, 마지막 "직원 교육 컨설팅은 / 엑스퍼트컨설팅."이 브랜드 임팩트(81.5초)에 떨어진다. 같은 내용을 기계가 읽을 수 있게 [`narration.json`](narration.json)에도 담았다.

## 1. 한눈에 보기

| 항목 | 값 |
|---|---|
| 방식 | 리드어롱(화면 문구를 목소리가 따라 읽음), 합니다체, 큐 20개, 약 209음절 |
| 모델 | `eleven_v4`, `language_code: "ko"` |
| 음성 | Jini - Warm & Intelligent (`0oqpliV6dVSr9XomngOW`), 남성 대안 Hoon - Calm Korean Narrator (`86GErZIiGJsPO3g7QNxZ`) |
| 설정 | stability 0.65(0.60–0.72), similarity_boost 0.80, speed·style은 보내지 않음(v4는 무시) |
| 생성 단위 | 블록 3개를 각각 한 번에 생성 → 큐 단위로 잘라 배치 |
| 비우는 구간 | 16.5–22.9초(20–21초 완전 정지 포함), 74.6–79.6초(소용돌이), 83.6초 이후 |

큐마다 따로 생성하지 않는 이유는 둘이다. v4 오디오 태그는 한 요청 안에서만 유지되고, "~하고,"처럼 쉼표로 끝나는 짧은 조각을 따로 만들면 문장 끝 억양으로 떨어진다.

## 2. Eleven v4에 넣을 입력문

블록마다 그대로 복사해 한 번씩 생성한다. 대괄호는 v4 오디오 태그(읽히지 않음)이고, `[short pause]`·`[pause]`·`[long pause]`는 자를 틈을 만들기 위한 것이다.

**블록 A — 문제 제기 (C01–C04)**

```text
[thoughtfully] 직원 교육, [pause] 어디서부터 시작해야 할까요? [long pause] 교육 과정은 늘어나는데, [short pause] 성과는 왜 그대로일까요? [pause] [firmly] 교육 따로, 현장 따로.
```

**블록 B — 해법·흐름·균형 (C07, C09–C15, C17–C19)**

```text
[confidently] 더 많은 과정이 아니라, 연결된 설계입니다. [long pause] [warmly] 인재를 알아보는 일부터, [short pause] 정확히 진단하고, [short pause] 교육체계를 설계하고, [short pause] 현장에서 함께 배우고, [short pause] 언제 어디서나 이어가고, [short pause] 몰입하는 배움의 공간까지, [short pause] 하나의 흐름으로. [long pause] 임원부터 팀장, 신입까지, [short pause] 성장의 무게를, [short pause] 하나의 균형으로.
```

**블록 C — 근거·명제·브랜드 (C21–C25)**

```text
[confidently] 천구백구십사 년 설립, 삼십 년 넘게 에이치알 한 길. [pause] 매년 함께하는 천 곳 이상. [pause] 성과는 누구와 설계하느냐에 달렸습니다. [long pause] 직원 교육 컨설팅은 [short pause] 엑스퍼트컨설팅.
```

- "은"과 "엑스퍼트" 사이의 `[short pause]`는 지우지 않는다. 없으면 [컨설팅으넥스퍼트]로 이어져 81.5초에 맞춰 자를 수 없다.
- 브랜드 문장만 다시 만들 때는 아래를 한 번에 생성하고, 앞 문장은 억양을 잡는 용도로만 쓰고 버린다.

```text
[confidently] 성과는 누구와 설계하느냐에 달렸습니다. [long pause] 직원 교육 컨설팅은 [short pause] 엑스퍼트컨설팅.
```

## 4. 생성 방법

### ElevenCreative(웹)

1. Text to Speech → 모델 **Eleven v4**, 음성 **Jini**, 언어 한국어.
2. Stability 슬라이더를 Natural과 Robust 사이(약 65%)에 둔다. 밋밋하거나 태그가 먹지 않으면 55%까지 내린다.
3. 블록 A·B·C를 하나씩 붙여넣고 블록마다 3–4번 생성해 가장 나은 테이크를 고른다.
4. 내려받은 파일을 편집기에서 `[pause]`·`[long pause]` 자리의 무음에서 자르고, 3장 표의 시각에 놓는다.

### API

자를 위치를 정확히 알려면 타임스탬프 엔드포인트를 쓴다. 응답의 `alignment`에 글자별 시작·끝 시각이 들어 있다.

```bash
curl -s -X POST \
  "https://api.elevenlabs.io/v1/text-to-speech/0oqpliV6dVSr9XomngOW/with-timestamps?output_format=mp3_44100_192" \
  -H "xi-api-key: $ELEVENLABS_API_KEY" -H "Content-Type: application/json" \
  -d '{
    "text": "<블록 A 입력문>",
    "model_id": "eleven_v4",
    "language_code": "ko",
    "apply_text_normalization": "auto",
    "seed": 1994,
    "voice_settings": { "stability": 0.65, "similarity_boost": 0.8 }
  }' > block_A_1994.json
```

- 테이크마다 `seed`를 바꾼다(1994, 1995, 1996, 1997).
- 블록 안의 큐는 가능하면 같은 테이크에서 가져온다. 테이크를 섞어도 되는 경계는 음악만 1초 넘게 흐르는 C01|C02, C07|C09, C15|C17, C23|C24뿐이다.
- 연결된 ElevenLabs MCP 도구(`creative_generate_speech`)는 seed, stability, 타임스탬프를 받지 않아 이 용도로는 맞지 않는다.

## 5. 자르기와 배치

- 첫 음절이 들리는 지점(약 -45dBFS, 앞에 10–20ms 여유)을 큐의 "발화 시작"에 맞춘다. 끝의 숨과 꼬리 무음은 잘라 낸다.
- 모음으로 시작하는 큐(어디서부터, 인재를, 언제, 임원부터, 엑스퍼트컨설팅)는 자동 트림에서 첫소리가 깎이기 쉬우니 귀로 확인한다.
- 창을 넘는 클립은 늦추거나 늘이지 말고 다른 테이크를 쓴다. 정류장 벨과 강조 장면이 어긋난다. C24만 최후 수단으로 포먼트를 보존한 3% 이내 압축을 허용한다.

검수 기준(실측):

| 큐 | 확인할 것 |
|---|---|
| C07 | "설계"가 25.4–25.7초(한계 25.9초). 넘으면 대체 문구로 블록 B 재생성 |
| C14 | 끝이 48.85초 이하. 넘으면 대체 문구 |

| C22 | "이상"이 69.85초 "+" 직후. "곳 이상"은 [고디상] 우선, [고시상] 허용 |
| C23 | 끝이 74.5초 이하. 넘으면 대체 문구를 71.2초에 |

발음과 태그도 테이크마다 확인한다. 에이치알, 천구백구십사가 바르게 읽히는지, 태그 단어가 소리로 읽히지 않았는지 듣는다.

## 6. 믹스

- 지금 배경음(`bgm.wav`)은 단독 감상용으로 크게 마스터링돼 있다(-13.8 LUFS, 실측). 전체를 약 10dB 낮추고, 음성이 나올 때 6–10dB를 더 덕킹한다(attack 약 50ms, release 약 400ms).
- 81.4–83.0초에는 임팩트와 벨을 음성 아래로 3–4dB 더 내린다. 그래야 "엑"이 묻히지 않는다.
- 최종은 -14 LUFS integrated, -1.5 dBTP를 목표로 한다.

## 7. 확인 필요

- **"천 곳 이상"의 근거:** 화면의 1,000+와 같은 수치(연간 1,000여 개 기업·공공기관)에 기댄다. README에 적은 대로 공식 소개 페이지와 대조가 필요하다.
- **발화 속도:** 시간 계산은 초당 4.8음절(느린 경우 4.3음절)을 가정했다. 사람 낭독 연구값(차분한 낭독 4.7–5.3음절/초)을 근거로 한 추정이며 실측이 아니다. v4에는 속도 조절이 없으니 첫 테이크의 길이로 보정한다.
- **v4 세부 사양:** 설정 항목(stability·similarity만 유효), 타임스탬프 엔드포인트의 v4 지원, 요청당 10,000자 제한은 elevenlabs.io를 이 환경에서 직접 열 수 없어 검색 요약과 연동 사례로 확인했다.
- **음성 추천:** 음성 설명과 대본 조건(빠듯한 큐, 장문 안정성)으로 고른 것이다. 미리듣기로 최종 결정한다.

## 8. 대본을 이렇게 쓴 이유

대본은 네 가지 전략으로 쓴 초안을 비교해 골랐다. 시간 맞춤, 설득력, 한국어·TTS 적합성, 사실 정확성의 네 기준으로 채점했다(40점 만점).

| 전략 | 점수 |
|---|---|
| 리드어롱(화면 문구 따라 읽기) | 32.5 |
| B2B 설득형 | 29.5 |
| 최소 발화형 | 27 |
| 보완 설명형 | 23.5 |

채택한 리드어롱안에 다른 초안의 좋은 줄을 옮겨 왔고, 이후 카피라이터·TTS 엔지니어·사실 감사 관점의 반박 검토로 다시 고쳤다. 주요 수정은 이렇다.

- "천여 곳"을 "천 곳 이상"으로 바꿨다. "천여"는 표준 발음이 [처녀]라 "함께하는 처녀"로 들릴 수 있다.
- 브랜드 문장을 한 요청으로 생성하게 했다. 둘로 나누면 이어 붙인 두 조각처럼 들린다.
- 감정 태그를 4종(thoughtfully, firmly, confidently, warmly)으로 줄였다. 장면마다 다른 성우처럼 들리는 것을 막기 위해서다.
- C23을 "성과는 누구와 설계하느냐에 달렸습니다."로 고쳤다. 앞서 쓴 "~느냐입니다"는 주어와 서술어가 맞지 않았다.
- C18을 화면 문구("성장의 무게를")에 맞췄다.
- 17.9–20초에는 음성을 넣지 않았다. 20초 완전 정지의 충격을 살리기 위해서다.
